# Contract intelligence demo

A short, offline tour of the Observatory using two deterministic WASM fixtures.

- `old.wasm` — `transfer(to, amount) -> bool`, `balance(owner) -> i128`, and a
  `Recipient` struct.
- `new.wasm` — `transfer` now returns `i128`, `balance` was removed, and `mint`
  was added.

The fixtures are generated by the checked-in example:

```bash
cargo run -p observatory-testutil --example make_demo_fixtures
```

## Run

```bash
bash demo/run-demo.sh
```

or on Windows:

```powershell
pwsh demo/run-demo.ps1
```

If `stellar-contract-platform` is not on `PATH`, the script uses
`cargo run -p observatory-cli --`.

## What it shows

1. `doctor` — tool and capability report.
2. `inspect --json` — bounded WASM metadata and the parsed interface.
3. `spec` — functions, structs, and the declared signatures.
4. `diff` — breaking, non-breaking, and informational changes.
5. `compat` — the compatibility decision and the reasons for it.
6. `fingerprint --json` — artifact and interface SHA-256 values.

## Expected output (abridged)

```text
$ stellar-contract-platform diff demo/fixtures/old.wasm demo/fixtures/new.wasm
changes: 2 breaking, 1 non-breaking, 0 informational
! function::balance: function `balance` was removed
! function::transfer: return type changed from `bool` to `i128`
+ function::mint: function `mint` was added
```

```text
$ stellar-contract-platform compat demo/fixtures/old.wasm demo/fixtures/new.wasm
status: incompatible
  breaking function `balance` was removed
  breaking return type changed from `bool` to `i128`
  note function `mint` was added
```

`compat` exits non-zero when the result is incompatible. That is the intended
CI behavior, so the demo reports it as an expected result.

## Reproducing the fixtures

The example uses the same `contractspecv0` builders as the test suite. It does
not execute WASM and does not need network access. The generated `.wasm` files
are committed so the demo works from a fresh clone.
